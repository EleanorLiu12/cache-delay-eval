Routing-relevant result

The experiment quantifies when cache locality stops being worth the queue

For a 1024-token prompt, reusing 512 cached tokens saved 102.5 ms at idle. At queue depth 2, that cached path took 1157.1 ms—4.8× the 240.1 ms TTFT of an uncached, idle replica.

What this means

A cache hit is a latency budget, not a routing rule

Cache locality should not be treated as a binary preference. A router should choose the cache-holding replica only when its additional queueing cost is smaller than the prefill time expected to be saved by reuse.

Choose the cache-holding replica when additional queueing cost < expected prefill time saved

01 · Interpretation

The experiment supplies an empirical cost model

The lookup turns prompt length, cached-prefix length, and queue depth into an expected TTFT. The routing decision can therefore compare predicted latency instead of choosing a server from cache hits alone.

02 · Scope

The measured boundary is system-specific

These values describe Qwen3-0.6B on vLLM-Metal and an Apple M3 Pro. This is a single-server calibration, not evidence yet about stale state or multi-replica routing behavior.

03 · Next step

Refine the boundary, then test routing policies

Queue depths 0, 2, and 8 show that the decision reverses before depth 2, but do not locate the exact crossover. Depth 1 is the next calibration point before the lookup is used in the two-replica emulator.

Experimental design

Controlled, audited, and resumable

  1. 01

    Exact prompts

    Token IDs fix prompt and block-aligned prefix lengths exactly for the server tokenizer.

  2. 02

    Observed queues

    Each probe begins only after server metrics confirm the requested running-plus-waiting depth.

  3. 03

    Manipulation checks

    Every accepted row matches its target prompt length, cache-hit tokens, and queue depth.

  4. 04

    Safe continuation

    Interrupted runs resume only after existing rows, configuration, and schedule identity are validated.

Protocol integrity

Failed and system-contaminated attempts were excluded, not erased

An early validation run revealed 32 unintended shared tokens, and later attempts encountered a desktop-wide latency shift under high GPU load. Those runs remain preserved locally for auditability but do not contribute to the published lookup, figures, or reported validation errors.
